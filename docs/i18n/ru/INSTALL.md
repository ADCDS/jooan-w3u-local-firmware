# Установка

Это руководство рассчитано на владельца камеры JOOAN W3-U, который умеет следовать
инструкциям и копировать команды, но не является специалистом по Linux. Сопровождающим
проекта, которые собирают собственные выпуски, нужен документ [Сборка и выпуск](../../../docs/BUILDING.md).

<a id="read-this-first"></a>
## Сначала прочитайте это

По состоянию на 2026-11-09 на странице
[GitHub Releases](https://github.com/ADCDS/jooan-w3u-local-firmware/releases) опубликованы следующие выпуски:

- **v0.2.21** (2026-10-16) — именно его установку описывают пронумерованные шаги этого
  руководства. Он устанавливается по Wi-Fi без дополнительного оборудования. Вы получаете локальную
  веб-консоль, SSH, видео по RTSP с обоих объективов, а также управление поворотом и
  предустановки по ONVIF для сетевого видеорегистратора (NVR), например Frigate; при этом
  камера больше не может связаться с облаком JOOAN. Видео по-прежнему выдаёт программа
  камеры от производителя, которая продолжает работать в изоляции.
- **v0.2.40** (2026-11-09) — последний выпуск. Он добавляет открытый медиадемон из каталога
  [`media/`](../../../media/), и именно эту версию описывает остальная документация репозитория.
  Камеру уже дважды перевели по этим инструкциям с заводской прошивки на v0.2.40 и его
  медиаслой. Прежде чем выбрать этот выпуск, прочитайте раздел [«Медиаслой»](#the-media-layer),
  в том числе о том, что проверено, а что нет.
- **Каждый из них устанавливается только на камеру, прошивка производителя которой
  совпадает с прошивкой проверенного экземпляра.** Прежде чем что-либо записать, установщик
  сравнивает файлы производителя с файлами проверенного экземпляра: v0.2.21 — весь раздел
  приложений, v0.2.40 — двенадцать файлов, от которых он зависит. Если они различаются,
  установщик отказывается от установки и оставляет камеру в прежнем состоянии. Медиаслой
  предъявляет к разделу приложений вашей камеры дополнительные требования: в нём должны быть
  все файлы, которые слой сохраняет, а в камере должны стоять сенсоры CV2005. Пока никто не знает,
  поставляются ли камеры, которые продаются сегодня, с той же прошивкой производителя.
- Ни один выпуск пока не является «поддерживаемым». Все выпуски на сегодняшний день —
  предварительные инженерные версии, проверенные на одной камере.

## По воздуху или с помощью оборудования?

| Что | Как | Дополнительное оборудование |
|---|---|---|
| Первая установка | По Wi-Fi, через встроенный веб-механизм обновления прошивки производителя | Не требуется |
| Последующие обновления и удаление | По Wi-Fi, в разделе Firmware («Прошивка») веб-консоли | Не требуется |
| Резервная копия флеш-памяти камеры | По SSH, после установки ([шаг 7](#7-back-up-the-camera-over-ssh)) | Не требуется |
| Резервное копирование или восстановление на уровне микросхемы | Программатором SPI-флеш-памяти с клипсой SOIC-8, при вскрытой камере | Для установки необязательно. Это единственный способ восстановить камеру, которая больше не загружается |
| Медиаслой (v0.2.40) | По Wi-Fi и SSH. Перезаписывает раздел приложений камеры | Для установки не требуется. Если во время записи пропадёт питание, вернуть камеру можно только с помощью программатора и резервной копии |

**Для установки v0.2.21 не нужны ни карта microSD, ни кабель USB, ни адаптер
последовательного порта, ни программатор флеш-памяти, и камеру не нужно вскрывать.**
Кабель Ethernet камеры в этих инструкциях не используется.

Карта microSD не нужна ни в каком случае. Если она вставлена, прошивка записывает на неё
журналы сбоев. В резервном режиме загрузки медиаслой может также запускать свои программные
файлы с карты, но это предназначено для сопровождающих проекта, а не для установки
(см. раздел [«Медиаслой»](#the-media-layer)).

## Что понадобится

- **Камера.** Это должна быть JOOAN W3-U, у которой на этикетке или в приложении
  производителя указана модель `JA-A12`. В других камерах, которые продаются под названием
  «W3-U», стоят другие микросхемы: прочитайте документ
  [Совместимость](../../../docs/COMPATIBILITY.md). Установщик проверяет модель и файлы
  производителя и отказывается работать с камерой, у которой они отличаются. Печатную плату
  он увидеть не может, поэтому единственная полная проверка — вскрыть камеру (в документе
  «Совместимость» объясняется, на что обращать внимание).
- **Мобильное приложение JOOAN.** Именно с помощью приложения прошивка производителя
  подключается к вашей сети Wi-Fi. Другого способа подключить к сети камеру с заводской
  прошивкой в этом проекте нет.
- **Маршрутизатор Wi-Fi**, такой, чтобы:
  - камера могла подключиться к сети WPA2. К одной точке доступа на OpenWrt с радиомодулем
    Qualcomm ath11k подключиться не удалось, а точки доступа на базе Realtek работали
    (см. [Совместимость](../../../docs/COMPATIBILITY.md#wi-fi-access-point-interoperability));
  - можно было закрыть доступ в интернет отдельному устройству. В маршрутизаторах это
    называется родительским контролем, контролем доступа или правилом брандмауэра;
  - ваш ПК находился в той же сети, что и камера.
- **ПК** с Windows 10 или новее, macOS или Linux, на котором есть:
  - Python 3.9 или новее;
  - пакет Python `cryptography`;
  - клиент SSH. Он встроен в Windows 10 и новее, macOS и Linux.
- **Около 30 минут** и стабильный источник питания для камеры (5 В, 1,5 А).
  Не отключайте камеру от питания во время установки.

## Пошаговая инструкция

### 1. Настройте камеру в приложении JOOAN

Пройдите обычную настройку в приложении и подключите камеру к той сети Wi-Fi, в которой
она будет работать постоянно. Сменить сеть камеры позже сложнее (см.
[шаг 8](#8-use-the-camera)). Приложение привязывает камеру через облако JOOAN, поэтому
сделайте это, пока у камеры ещё есть доступ в интернет: на шаге 3 он будет закрыт.
(В прошивке производителя есть также точка доступа для настройки и получение адреса по
DHCP через Ethernet, которые, возможно, позволяют обойтись без приложения; ни один из этих
способов с данным руководством не проверялся.)

Если приложение предложит обновить прошивку камеры, откажитесь. В более новой прошивке
производителя меняются файлы, которые проверяет установщик, и тогда установщик откажется
работать с этой камерой.

**Всё получилось, если** приложение показывает видео с камеры в реальном времени.

### 2. Узнайте IP-адрес камеры

Найдите камеру в списке подключённых устройств маршрутизатора. Прошивка производителя
запрашивает у маршрутизатора адрес под именем `JAIPC`. MAC-адрес камеры указан в сведениях
об устройстве в приложении. Полезно закрепить адрес за камерой в настройках DHCP
маршрутизатора, чтобы он не менялся.

**Всё получилось, если** камера отвечает на `ping CAMERA_IP` с вашего ПК. Здесь и
далее заменяйте `CAMERA_IP` найденным адресом, например `192.168.1.50`.

### 3. Закройте камере доступ в интернет

На маршрутизаторе закройте доступ в интернет камере — и только ей. Ваш ПК должен
оставаться в той же сети.

При каждом включении в течение нескольких секунд, пока управление не перейдёт к этой
прошивке, работают веб-сервер и механизм обновления производителя. Благодаря блокировке в
этот промежуток у них нет выхода в интернет. С этого момента приложение JOOAN больше не
может связаться с камерой. Так и должно быть.

**Всё получилось, если** приложение показывает, что камера не в сети, а `ping CAMERA_IP`
по-прежнему получает ответ.

### 4. Подготовьте ПК

Скачайте в одну новую папку:

1. **Исходный код v0.2.21** по ссылке
   <https://github.com/ADCDS/jooan-w3u-local-firmware/archive/refs/tags/v0.2.21.zip>.
   Распакуйте архив — получится папка `jooan-w3u-local-firmware-0.2.21`.
2. Следующие шесть файлов со
   [страницы выпуска v0.2.21](https://github.com/ADCDS/jooan-w3u-local-firmware/releases/tag/v0.2.21).
   Сложите их вместе в папку с именем `release` рядом с папкой исходного кода:
   `JOOAN_FW_PKG`, `JOOAN_FW_PKG.sha256`, `JOOAN_UNINSTALL`,
   `JOOAN_UNINSTALL.sha256`, `manifest.json` и `manifest.json.sig`.

Исходный код должен быть именно версии v0.2.21, а не из текущей ветки `main`. Текущая
версия инструмента загрузки отклоняет пакет v0.2.21 с ошибкой `signed release target/ABI contract does
not match this repository`.

Установите `cryptography`.

Linux или macOS:

```sh
python3 -m pip install --user cryptography
```

В Debian или Ubuntu подойдёт и `sudo apt install python3-cryptography`.

Windows (командная строка):

```bat
py -m pip install cryptography
```

**Всё получилось, если** эта команда выводит номер версии:

```sh
python3 -c "import cryptography; print(cryptography.__version__)"
```

В Windows здесь и на шаге 5 вводите `py` вместо `python3`.

### Доставка по воздуху: как камера на самом деле получает пакет

Прочитайте этот раздел перед шагом 5. Заводской механизм обновления сам **забирает** пакет
из облака, а не принимает загружаемый на камеру файл. `tools/upload_ota.py` запускает его,
но то, что инструмент отправляет POST-запросом, игнорируется: после этого камера скачивает
прошивку по фиксированному облачному URL-адресу
`https://use1api.jooaniot.com/fw/JOOAN_FW_PKG` через TLS. Поэтому, помимо запуска
инструмента, для установки нужно выполнить ещё два условия:

1. **Для камеры имя `use1api.jooaniot.com` должно разрешаться в адрес ПК, который будет
   раздавать пакет.** Именно это чаще всего упускают из виду. Камера **игнорирует
   DNS-сервер, который ваш маршрутизатор выдаёт по DHCP**, и обращается к жёстко заданным
   публичным DNS-резолверам (223.6.6.6 и 8.8.8.8). Смена «вашего DNS» ничего не даст.
   Перенаправление должно происходить на сетевом пути. Работают два способа:

   - **Маршрутизатор, который подменяет это имя для камеры.** В OpenWrt это одна строка
     dnsmasq, `address=/use1api.jooaniot.com/<PC-IP>`, плюс правило брандмауэра, которое
     **перенаправляет собственный трафик камеры на порт 53 на DNS-резолвер маршрутизатора**
     (DNAT обращений камеры к UDP/TCP-порту 53 на маршрутизатор), потому что иначе камера
     обходит DNS маршрутизатора. Ограничьте действие обоих правил MAC-адресом камеры.
   - **Отдельное устройство для перенаправления DNS в подсети камеры**, которое на запрос
     этого единственного имени отвечает адресом ПК, а все остальные запросы пересылает
     дальше; трафик камеры на порт 53 точно так же направляется на него.

   Имитировать остальную часть облака не нужно — только это одно имя хоста и только для
   скачивания прошивки.

2. **ПК должен раздавать пакет по TCP-порту 443.** `tools/serve_ota.py` делает ровно это
   и ничего больше: на запрос `/fw/JOOAN_FW_PKG` он отдаёт указанный вами файл по TLS с
   самоподписанным сертификатом (камера его не проверяет), а на любой другой путь отвечает
   кодом 404. Он не выдаёт себя за облачный API, ничего не пересылает вышестоящим серверам и
   не трогает учётные данные устройства.

Если камера уже работает на jooan-local (то есть это последующее обновление, а не первая
установка), ничего из этого не требуется: обновления проходят через API `/api/v1/update`
с аутентификацией, а не через скачивание из облака.

### 5. Установите прошивку

Запустите раздачу пакета. В папке `jooan-w3u-local-firmware-0.2.21` выполните в одном
терминале (чтобы занять порт 443, нужны повышенные привилегии; в Linux используйте `sudo`):

```sh
sudo python3 tools/serve_ota.py --pkg ../release/JOOAN_FW_PKG
```

Сервер выводит `[ready] https://0.0.0.0:443/fw/JOOAN_FW_PKG` и создаёт одноразовый
сертификат для `use1api.jooaniot.com`. Оставьте его работать. Настройте перенаправление
DNS, описанное в предыдущем разделе, чтобы камера обращалась к этому серверу.

Затем во втором терминале в той же папке запустите обновление на камере:

```sh
python3 tools/upload_ota.py --host CAMERA_IP --pkg ../release/JOOAN_FW_PKG
```

Инструмент проверяет подпись пакета, запускает механизм обновления производителя на камере
(тот скачивает пакет с запущенного выше сервера) и ждёт, пока камера перезапустится с новой
прошивкой. Когда камера заберёт пакет, в терминале сервера появится
`[served] /fw/JOOAN_FW_PKG -> ... bytes`. Это займёт от одной до пяти минут. Не отключайте
питание камеры.

**Всё получилось, если** последняя строка выглядит так:

```text
[+] jooan-local is active
```

Если не получилось:

| Сообщение | Что это значит и что делать |
|---|---|
| `error: signed release target/ABI contract does not match this repository` | У вас другая версия исходного кода. Используйте zip-архив v0.2.21 из шага 4 |
| `... requires the Python 'cryptography' package` | Установите его, как описано на шаге 4 |
| `[-] unexpected OEM response HTTP ...` | Механизм обновления производителя на камере отклонил запрос на запуск. На этом остановитесь |
| Терминал сервера так и не выводит `[served] ...` | Камера не смогла связаться с вашим сервером. Почти всегда причина в перенаправлении DNS: убедитесь, что `use1api.jooaniot.com` разрешается в адрес вашего ПК **со стороны камеры** и что трафик камеры на порт 53 перенаправляется (DNS-сервер из DHCP она игнорирует). Проверьте, что на ПК открыт порт 443 |
| `[-] package upload completed but jooan-local did not become healthy` | Камера приняла пакет, но эта прошивка не запустилась. Скорее всего, установщик обнаружил другие файлы производителя и отказался работать с камерой, ещё ничего не записав. На камере остаётся прошивка производителя. На этом остановитесь и прочитайте раздел [«Если что-то пошло не так»](#if-something-goes-wrong) |
| Ответа нет вовсе | Проверьте `CAMERA_IP` и убедитесь, что ПК и камера находятся в одной сети |

### 6. Войдите в веб-консоль

Откройте в браузере `http://CAMERA_IP/` и войдите:

```text
username: admin
password: admin
```

Пароль остаётся `admin`, пока вы не смените его в разделе System («Система»). Этот же
пароль используется для SSH и RTSP, поэтому смена пароля действует сразу для всех трёх.

**Всё получилось, если** по адресу `http://CAMERA_IP/api/v1/setup/status` отображается
`"release_version":"0.2.21"`.

<a id="7-back-up-the-camera-over-ssh"></a>
### 7. Сделайте резервную копию камеры по SSH

Рекомендуется. Так вы без дополнительного оборудования сохраните на ПК копию каждого
раздела флеш-памяти. Только эта копия сможет вернуть эту камеру к работе, если последующее
обновление пойдёт не так: содержащиеся в ней файлы производителя нигде не опубликованы.
Для восстановления камеры, которая больше не загружается, понадобится ещё и программатор
флеш-памяти (см. [Восстановление](./RECOVERY.md#external-spi-recovery)).

У камеры семь разделов, от `mtd0` до `mtd6`. Эта команда выводит их список:

```sh
ssh admin@CAMERA_IP cat /proc/mtd
```

Затем сохраните каждый раздел. Выполните каждую команду и введите пароль, когда его
запросят. В Windows используйте командную строку (Command Prompt), а не PowerShell.
Перенаправление `>` в Windows PowerShell повреждает двоичные файлы.

```sh
ssh admin@CAMERA_IP "cat /dev/mtdblock0" > camera-mtd0.bin
ssh admin@CAMERA_IP "cat /dev/mtdblock1" > camera-mtd1.bin
ssh admin@CAMERA_IP "cat /dev/mtdblock2" > camera-mtd2.bin
ssh admin@CAMERA_IP "cat /dev/mtdblock3" > camera-mtd3.bin
ssh admin@CAMERA_IP "cat /dev/mtdblock4" > camera-mtd4.bin
ssh admin@CAMERA_IP "cat /dev/mtdblock5" > camera-mtd5.bin
ssh admin@CAMERA_IP "cat /dev/mtdblock6" > camera-mtd6.bin
```

**Всё получилось, если** размеры семи файлов в сумме составляют 8388608 байт (8 МиБ), а
сумма MD5 для `camera-mtd4.bin` (раздел приложений), вычисленная на камере:

```sh
ssh admin@CAMERA_IP md5sum /dev/mtdblock4
```

совпадает с суммой, вычисленной на ПК: `md5sum camera-mtd4.bin` (Linux),
`md5 camera-mtd4.bin` (macOS) или `certutil -hashfile camera-mtd4.bin MD5`
(Windows).

В этих файлах хранятся идентификационные данные этой камеры, её пароль от Wi-Fi и её ключи.
Храните их в тайне, никому не передавайте и никогда не записывайте их на другую камеру.

<a id="8-use-the-camera"></a>
### 8. Пользуйтесь камерой

С выпуском v0.2.21:

- **Видео:** RTSP на порту 554, пользователь `admin` и пароль администратора.
  `rtsp://CAMERA_IP:554/live/ch0` — объектив на поворотной головке,
  `rtsp://CAMERA_IP:554/live/ch1` — неподвижный объектив.
- **Поворот и предустановки:** ONVIF по адресу `CAMERA_IP`, порт 80, те же пользователь и
  пароль.
- **SSH:** `ssh admin@CAMERA_IP`, тот же пароль.
- **Wi-Fi:** камера остаётся в той сети, которую настроило приложение. Чтобы перевести её
  в другую сеть, укажите новую сеть в веб-консоли в разделе Network → Wi-Fi («Сеть» →
  Wi-Fi), примените её пробно (stage), а когда камера переподключится, подтвердите
  (commit). Изменение, которое так и не было подтверждено, откатывается.
- **Часы:** у камеры нет часов с батарейным питанием. После отключения питания нажмите
  «Sync time & zone to this device» (синхронизировать время и часовой пояс с этим
  устройством) в разделе System → Camera time («Система» → «Время камеры»).

Эти возможности описаны в документации v0.2.21. Читайте её в версии, отмеченной тегом:
[README](https://github.com/ADCDS/jooan-w3u-local-firmware/blob/v0.2.21/README.md)
и [API](https://github.com/ADCDS/jooan-w3u-local-firmware/blob/v0.2.21/docs/API.md).
Документы в ветке `main` описывают 0.2.40.

<a id="updating-later"></a>
## Последующие обновления

Новый опубликованный выпуск устанавливайте из веб-консоли. В разделе Firmware («Прошивка»)
выберите его файл `JOOAN_FW_PKG`, дождитесь сообщения «signature verified» («подпись
проверена»), затем примените его. Камера перезагрузится и примерно 90 секунд будет
недоступна. Выпуск принимается, только если он подписан этим проектом и новее
установленного.

**Не обновляйте камеру с v0.2.21 до 0.2.22 или более поздней версии, если не собираетесь
сразу после этого установить медиаслой.** Начиная с 0.2.22 платформа сама больше не выдаёт
видео, поэтому до установки медиаслоя видео на камере не будет.

Выпуски после 0.2.21 отвечают только на запросы, в которых камера адресуется по частному
IP-адресу или по собственному имени. Имя — `jooan-w3u`, если вы не смените его в разделе
Network → Local name («Сеть» → «Локальное имя»). Его можно использовать без суффикса или с
окончанием `.local`, `.lan`, `.home.arpa` или `.internal`, например `jooan-w3u.local` или
`jooan-w3u.lan`. На любое другое имя возвращается `403 host_rejected` (см. документ
[Сетевая безопасность](../../../docs/NETWORK-SECURITY.md#host-and-origin-checks)).

## Удаление

В разделе Firmware («Прошивка») примените файл `JOOAN_UNINSTALL` из того выпуска, который
вы установили. После перезагрузки камера снова работает на прошивке производителя, уже без
изоляции: возвращается веб-сервер производителя, и камера снова может связаться с облаком,
если только маршрутизатор по-прежнему её не блокирует. Собственные настройки Wi-Fi прошивки
производителя на камере сохраняются. Настройки платформы, включая подтверждённую в ней сеть
Wi-Fi, удаляются. Подробности — в документе
[Восстановление](./RECOVERY.md#booting-camera-rollback).

**Если установлен медиаслой, удаление его не убирает.** Его файлы в `/opt/jooanipc-open`,
в том числе пароль потоков и закрытый ключ TLS, остаются на месте, поэтому сначала удалите
их по SSH: `rm -rf /opt/jooanipc-open`. Раздел приложений тоже остаётся урезанным — без
голосовых подсказок производителя и драйверов других сенсоров. **Не пытайтесь записать
исходный раздел обратно на работающей камере:** программа, работающая из этого раздела,
аварийно завершается, как только раздел начинает стираться, а если камера перезагрузится до
окончания записи, вернуть её можно будет только программатором флеш-памяти. Чтобы вернуть
исходный раздел, нужны программатор флеш-памяти и сохранённый вами файл `my-appfs.img`.

<a id="if-something-goes-wrong"></a>
## Если что-то пошло не так

- **После шага 5 камера загружает прошивку производителя.** Если установщик отказался
  работать с камерой, он ничего не записал, и камера осталась без изменений. Вернуться к
  приложению JOOAN можно, сняв блокировку на маршрутизаторе.
- **После обновления веб-консоль или SSH перестали отвечать.** Один раз выключите и снова
  включите питание камеры и подождите три минуты. Если она по-прежнему не отвечает,
  следуйте инструкциям из документа [Восстановление](./RECOVERY.md).
- **Камера вообще перестала загружаться.** Вернуть её может только восстановление вашей
  резервной копии на уровне микросхемы с помощью программатора флеш-памяти
  ([Восстановление](./RECOVERY.md#external-spi-recovery)).

Обращаясь за помощью, никогда не публикуйте образы флеш-памяти, пароли или ключи (см.
документ [Политика безопасности](../../../SECURITY.md#reporting-a-vulnerability)).

<a id="the-media-layer"></a>
## Медиаслой

Начиная с 0.2.22 видео, ONVIF и управление поворотом обеспечивает открытый медиадемон
[jooanipc-open](../../../media/), а не программа производителя. При штатной загрузке,
которая начиная с 0.2.23 используется по умолчанию, программа производителя вообще не
запускается. Именно такую конфигурацию описывает остальная документация репозитория.

**Вся эта цепочка — от заводской прошивки до открытого стека — теперь дважды пройдена на
реальной камере.** Тестовую камеру вернули к подлинной заводской прошивке, подключили к Wi-Fi
без приложения производителя, установили на неё платформу по воздуху, а затем прошили
медиаобразом, собранным из её собственного раздела. Камера отдавала видео по RTSP и пережила
холодную перезагрузку на открытом стеке. Что проверил первый прогон и что пока проверено
недостаточно:

| Этап | Что проверено |
|---|---|
| Возврат к заводской прошивке | Тестовую камеру прошили обратно заводским разделом (с обслуживанием сторожевого таймера и возможностью отката из копии в ОЗУ), и она загрузилась с подлинной заводской прошивкой в ненастроенном состоянии |
| Настройка без приложения | С находящегося рядом ПК запрос `GET /goform/setupWifiInfo` к точке доступа SoftAP камеры перевёл её на Wi-Fi; камера сообщила об успехе и подключилась к сети |
| Установка платформы по воздуху | Когда обращения к облаку были перенаправлены на локальный сервер, камера скачала и применила подписанный пакет платформы, а затем загрузилась с ней |
| Образ | Собран из настоящего заводского раздела; файлы побайтно совпадают с заведомо исправным медиаобразом |
| Конфигурация | То, что записывает установщик, проходит собственную проверку поставляемого демона |
| Установщик | Его решения, порядок действий и предварительные проверки — как на имитации камеры, так и на реальной камере; он правильно отказывался продолжать, пока не были готовы платформа и Wi-Fi |
| Скрипт прошивки `first-appfs.sh` | Выполнен по-настоящему: записал медиаобраз, сохранил возможность отката из ОЗУ, а открытый демон довёл штатную загрузку до успешной квалификации и обслуживал сторожевой таймер |
| Переживает перезагрузку | После полного отключения и повторного включения питания камера снова загрузилась с открытого медиаобраза и отдавала RTSP, без отката к заводской прошивке |
| Установка 0.2.39 с заводской прошивки | Выполнена в ходе этого же прогона через тот же механизм обновления |

Две шероховатости, обнаруженные в ходе этого прогона, исправлены в v0.2.40, после чего вся
цепочка была пройдена с заводской прошивки во второй раз — уже с этим выпуском:

- **Открытую** (без пароля) сеть Wi-Fi теперь можно подтвердить через платформу
  (подключение выполняется с `key_mgmt NONE`); сети WPA2 работают, как и прежде.
- На только что установленной платформе в разделе `/opt` объёмом 384 КиБ может немного не
  хватить места для первой установки медиаслоя. Теперь в этом случае установщик
  автоматически освобождает место, удаляя заводской файл `/opt/conf/config.org`, который
  можно воссоздать, — при условии, что есть заводская копия для его восстановления
  (при загрузке заводской прошивки этот файл воссоздаётся из `/mnt/mtd/etc`).

Если контрольное чтение после записи выявит расхождение, скрипт восстановит раздел из копии
в ОЗУ. **Если во время записи пропадёт питание, вернуть камеру смогут только программатор
флеш-памяти и резервная копия этого раздела** (см.
[Восстановление](./RECOVERY.md#appfs-reflash-recovery)). Прошивка уже была выполнена до
конца на реальной камере несколько раз за два полных цикла, но лишь на одном этом
устройстве; поэтому сначала сделайте полную резервную копию
всех разделов (установщик делает это сам) и обеспечьте камере стабильное питание на те
несколько минут, которые занимает запись.

Вам понадобится компьютер с Linux или WSL, на котором установлены `squashfs-tools`,
Python 3, OpenSSH и OpenSSL, а также файлы v0.2.40 со страницы выпуска.

1. **Установите платформу.** Выполните шаги 4 и 5 с исходным кодом и файлами v0.2.40
   либо обновитесь с v0.2.21, как описано в разделе [«Последующие обновления»](#updating-later).
   С этого момента видео на камере не будет до последнего шага. Веб-консоль по-прежнему
   доступна по адресу `http://CAMERA_IP/`.
2. **Сделайте резервную копию камеры** ([шаг 7](#7-back-up-the-camera-over-ssh)).
3. **Подтвердите сеть Wi-Fi камеры** в веб-консоли в разделе Network → Wi-Fi («Сеть» →
   Wi-Fi), даже если камера уже подключена именно к ней. При штатной загрузке используется
   только сеть, подтверждённая там, а не та, которую настроило приложение JOOAN.
4. **Распакуйте** `jooanipc-open-*.tar.gz` и `libimp-*.tar.gz` рядом друг с другом
   и откройте терминал в папке `jooanipc-open-*`.
5. **Скопируйте раздел приложений вашей камеры и соберите из него свой образ.**
   Оба содержат файлы производителя, поэтому храните их в тайне:

   ```sh
   ssh admin@CAMERA_IP 'cat /dev/mtdblock4' > my-appfs.img
   sh media/tools/build-appfs.sh --first my-appfs.img bin/jooanipc-open ../libimp-*/libimp.so bin/libatomic.so.1 my-bundle
   ```

   Скрипт откажется работать с разделом, в котором нет нужного ему файла или программа
   производителя отличается от той, которую закрепляет платформа.

6. **Проверьте камеру.** Эта команда ничего не меняет:

   ```sh
   CAMERA_PASSWORD=admin python3 media/scripts/install-camera.py my-bundle --camera CAMERA_IP
   ```

7. **Выполните установку**, задав пароль для видеопотоков камеры:

   ```sh
   CAMERA_PASSWORD=admin STREAM_PASSWORD=your-choice python3 media/scripts/install-camera.py my-bundle --camera CAMERA_IP --yes-untested
   ```

   Не отключайте питание камеры. **Всё получилось, если** в последней строке сказано, что
   выпуск запущен. Интерфейс администрирования теперь доступен по адресу
   `https://CAMERA_IP/` с собственным сертификатом камеры, поэтому браузер один раз выдаст
   предупреждение. Войдите с паролем администратора. `http://CAMERA_IP/` теперь только
   перенаправляет туда.

Загрузка проверяет сама себя: если штатная загрузка зафиксировала сбой или трижды подряд
прерывалась, следующая загрузка переходит в резервный режим с программой производителя.
То же происходит, если при штатной загрузке через 5 минут нет шлюза, — до тех пор, пока
штатная загрузка хотя бы раз не пройдёт квалификацию (см.
[Восстановление](./RECOVERY.md#a-media-change-that-stops-native-boot)).

**В Windows** соберите комплект в WSL, а затем запустите установщик командой `py` в
командной строке, задав каждый пароль через `set`. Установщик использует OpenSSH, который
поставляется с Windows, и требует наличия `openssl` в PATH — он входит в состав Git for Windows.
OpenSSH 8.4 и новее (Windows 11) берёт пароль из `CAMERA_PASSWORD`; версия из Windows 10
запрашивает его при каждом подключении, поэтому сначала добавьте ключ SSH в веб-консоли.
В Windows это тоже ещё не проверялось.

**Последующие обновления медиаслоя** начинаются с текущего раздела вашей камеры: образ
собирается с помощью `build-appfs.sh` без `--first`, и для этого нужен файл `bundle.json`,
который вы пишете сами (см. раздел
[«Комплекты выпуска для камеры»](../../../media/docs/hardware.md#camera-release-bundles)).
Установщику в этом случае нужен также `MEDIA_PASSWORD` — пароль потоков, — чтобы проверить
результат. Форма «Система» → «Медиа» (System → Media) в интерфейсе администрирования
принимает только пакеты, подписанные ключом выпусков этого проекта. Каждое обновление
медиаслоя — и установщиком, и через эту форму — перезаписывает тот же раздел, что и первая
установка, поэтому приведённое выше предупреждение о потере питания относится и к нему — в том
числе к перезагрузкам самой платы. Поскольку образ содержит файлы производителя, ни один
образ не публикуется, так что эта форма предназначена для владельца ключа или для тех, кто
собирает платформу со своим собственным ключом.

**SD-карта:** в резервном режиме загрузки медиаслой может запускать демон с карты microSD
вместо раздела приложений. Карту монтирует только программа производителя, поэтому это
работает лишь в резервном режиме. Это не способ обойти какой-либо из описанных выше шагов.

Формат комплекта описан в разделе
[«Комплекты выпуска для камеры»](../../../media/docs/hardware.md#camera-release-bundles).
